## 一、重点深挖

### oh-story-claudecode（zenstory-ai）— 与 story-forge 气质最接近

8,299★ · 当天仍在推送 · 14 个 skill 装进 7 款编程 Agent。

**核心架构**：文件系统当记忆 + 7 专业 Agent + hooks 门禁。`追踪/_tracking-state.json` 为**唯一结构化权威**，人类可读视图（续写状态卡、伏笔视图、角色状态快照、双时间线）全部派生，手改派生文件被 `check` 拒绝；章级提交 `storyctl.py chapter commit` 带 `state_revision` 版本号。

- **人物卡**：静态/动态物理分离——`设定/角色/{角色名}.md`（档案）与 `追踪/角色状态/{角色名}.md`（随章快照）两份文件。动态时间线拆两层：`时间线/作者真相.md`（真相候选编号 E015，揭示前不算读者已知）与 `读者已知.md`。纪律：真相候选可在第 22 章细纲前改掉、状态退役要登记、不允许静默消失。
- **章节讨论流**：细纲硬门禁——`guard-outline-before-prose.sh` 缺细纲时**阻断**正文首次写入；细纲规格 =「本章必须发生什么变化」：单元编号 L1-03、目标情绪、本章标价、闭环状态、10 个情节点四列表。写后确定性检查（AI 句式/退化/标点）再 commit。
- **bible 组织**：`设定/`（世界观按主题、角色一人一文件、势力一组织一文件、关系.md、题材定位.md）+ `大纲/`（全书卷级→卷纲〔爽点节奏+情绪弧线+人物弧线+伏笔+反转〕→每章细纲）三层；`对标/` 目录把拆解的爆款书结构化为同构资产。两级「作者记忆」（全局 AP + 每书 BP 编号，含待确认池与变更记录）。
- 模型分级（Opus 架构/写手、Sonnet 角色设计、Haiku 一致性/检索）可映射我们的多模型阵容。

### agent-novel（RTY798）— star 只有 6，工作流契约全场最干净

`story-state.json` + 追加式 `chapter-log.jsonl`，上下文 **HOT/WARM/COLD 三层**只加载本章需要的事实；章节 A 情绪章/B 动作章/C 桥接章三型；铁律「事实是数据，文字是艺术」。

- **章节卡模板（原样可抄为讨论表单）**：`chapter_type / creative_release / viewpoint+时态 / 时空 / opening state / chapter objective / obstacle / irreversible or meaningful choice / recorded consequence / reader promise(画面|情绪|事件|信息四选) / ending state / allowed facts / prohibited developments / active hooks touched` + Story Contract 三问（**Change / Promise / Aftermath**）+ 场景节拍（目标→阻力→选择→后果）。
- 指令模式：「先给 3-5 个节拍，不写正文，等我确认不可逆选择后再出首稿和独立的 STATE_DELTA」；关键分歧给 **A/B/C 三案由作者选**。
- 人物卡：建书只填五项（书名、类型+读者、一句话前提、**主角不可变锚点**、篇幅）——「不要在正文开始前制造一部无人验证的百科全书」。
- bible：HOT（本章必知）/WARM（近期相关）/COLD（按需检索）= 每个条目标「本章可见性」，与信息防火墙直接拼接。

## 二、引擎类

**Narcooo/inkos** · 11,000★：Studio 网页工作台 + TUI + CLI，19 个 SKILL.md，SQLite FTS5/BM25 检索投影（原始文件仍是权威）。**剧情多线推演**——写前基于正史生成 2-5 条隔离分支，横向比较节拍/人物决定/预计变化/风险/作者意图匹配度；采纳只存 `selected-branch-plan.md` 候选计划不动正文，正史推进后旧推演自动过期。另有「安全章节工作区」（正文/状态/伏笔先校验再原子提交）。

**voocel/ainovel-cli** · 2,283★：确定性引擎 + 语义裁定分离（Route 决策表零 LLM 派发，模糊处唤醒 Arbiter 落盘可回放）。**卷弧双层滚动规划**（「指南针」=终局方向+活跃长线，初始只规划 2 卷骨架+第 1 弧细章，写到再展开）；每章从伏笔/角色出场/状态变化/关系四维反查推荐历史章节；压缩后注入「恢复包」防失忆。

**wanqili857-byte/fictionforge** · 56★ 但字段设计惊艳：「每个角色都是一个 agent」（memories/beliefs/knowledge 三件套，配角镜头外也过日子）；Narrator 合成章节 spec（标注反转落点）后生成正文。①**canon/drafts 分家**——AI 只写 `chapters/drafts/`，人工定稿才是 canon，引擎永不覆盖；②**修订即资产**——diff 定稿 vs 原稿、标注修订原因（AI味/节奏/素材/逻辑），蒸馏成素材库回灌（配额新进旧出，prompt 不膨胀）；③**CanonBench**——零 LLM 可审计的长程一致性判定器：死亡/物品/位置/时间线入状态账本，真相表标「谁在第几章知道什么」，判定器自己也要被测（真实误报进测试夹具）。

**mrigankad/Novel-OS** · 55★：五角色 Agent，输出强制带 `[SCRIBE_STATE_UPDATE]` 块合并进中央 `story_state.json`；确定性 Continuity Engine 先跑、LLM Guardian 后跑。**三模式（Plan/Write/Revise）而非四阶段流水线**，「管道阶段降级为 provenance」；Write 模式「不打扰」；Revise 模式每条一致性发现可标 **"This is intentional"**，豁免持久化进状态文件，Guardian 不再重翻旧账。

**YILING0013/AI_NovelGenerator** · 6,401★：唯一正经数据库工作台（Python + Next.js + MongoDB 多文档事务）。规划链：方向→核心（阵营/角色/关系）→卷→弧→场景→章计划；**人物/阵营/关系可视化图**；「AI 出候选→人工审阅→保存」候选制交互。6.4k 星验证「带 UI 工作台」需求真实；信息架构（左规划树/中编辑器/右角色事实面板）可作 UI 参照。

**学术线**：THU-KEG/StoryWriter（Outline 事件大纲含事件间关系→Planning 拆章→Writing 动态压缩历史）；RecurrentGPT（计划先行于正文鼻祖）；Dramatron（logline→人物→情节→场景→对白层级 prompt 链，每层人类可改）。

## 四、三焦点横向提炼

**① 人物卡四分区**：
- **恒定区**（抄 agent-novel 锚点 + CCv3 mes_example）：不可变人格事实、3-5 条真实对话样本（不是形容词）
- **动机区**（我们的独家）：want/need/wound/value/fear/contradiction/voice 栈 + 本章动机压力引用
- **知识区**（抄 oh-story + talemate）：当前知道什么（读者已知层）/不知道什么（作者真相层，带揭示条件）/Never-Learn 红线
- **动态区**（抄 oh-story 物理分离）：位置、伤势、持有物、关系状态——独立快照文件，随章 commit 更新

**② 章节讨论→大纲→落笔**：讨论用 **InkOS 多线推演**（2-5 分支隔离比较）或 agent-novel A/B/C 三案 → 定稿进 **agent-novel 章节卡**（四元组细胞作字段族嵌入）→ **oh-story 门禁**（无章节卡阻断正文）→ 落笔后 STATE_DELTA 分离生成、确定性检查、commit 带版本号。人类介入点三个：选分支、改章节卡、定稿。

**③ bible 组织**：oh-story 目录学（设定/大纲/追踪三区）+ agent-novel HOT/WARM/COLD 分级 + CCv3 关键词触发注入；伏笔条目 = 带埋设章/回收章/优先级/真相候选引用的 bible 实体。

## 六、抄谁抄什么

| story-forge 模块 | 抄谁 | 抄什么 |
|---|---|---|
| 人物设定管理 | CCv3 + oh-story | 四分区；静态档案与动态快照分文件；对话样本代替形容词 |
| 章节讨论流 | agent-novel + InkOS | 章节卡结构化载体；多线推演；采纳只写候选计划不动正史 |
| 大纲→落笔门禁 | oh-story + FictionForge | 无章节卡阻断正文；canon/drafts 分家+修订回灌 |
| story bible | oh-story + NovelCrawler 概念 | 三区目录学；伏笔=带生命周期的 bible 实体 |
| 信息防火墙 | talemate + FictionForge | Learn/Never-Learn；双账本；判定器也要被测 |
| 滚动规划 | ainovel-cli | 指南针+只展开当前弧 |
| 多模型分工 | oh-story | 强模型架构正文、快模型校验检索 |

**诚实提醒**：没有谁同时做好「人物卡+讨论流+bible」三件事。我们的动机栈和读者模拟器是全场独有层，拼装完在「人物深度×流程纪律」象限没有直接对手。
