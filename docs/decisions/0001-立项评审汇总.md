## 一、四方共识（独立撞车，高置信）

### 共识 1：立项通过，但必须"先证伪、后开发"

四方无一例外。没有人驳回构想，但全部要求第一阶段不是建引擎，而是跑一个能**杀死**这个构想的对照实验。实验失败就转向"显式台账 + 行为约束"路线（ainovel-cli 路线的强化版），不沉没成本。

### 共识 2：病根诊断不完整——泄底有两条成因，防火墙只治其一

四方独立指出同一个裂缝：

- **成因 A（信息可见性）**：作者知道结局，忍不住埋钩。防火墙对症。
- **成因 B（生成习惯）**：RLHF 训练出的"张力闭合"倾向 + 单章缺乏局部目标。模型看不到暗账，也会自造伏笔并两章内自我揭穿。防火墙对此**零作用**。

旁证：ainovel-cli 明知伏笔回收时机仍要配 forbidden_moves 和前向引用机械校验来压泄底；且它的 `novel_context` 本就不含全书大纲（`novel_context_test.go:294` 有断言），泄底问题依然存在。

**裁决：成立。** 项目前提从"防火墙是解药"修正为"防火墙是待验证的假设，配比未知，由实验裁决"。

### 共识 3：防火墙落在工具层确定性过滤，否决导演 agent 动态裁定

四方全部否决了"导演 LLM 裁定可见性"：裁定者必须全知才能裁定，等于把要消灭的全知点请回来，且每次裁定不可复现、可被注入、还构成侧信道（"这条被裁掉了"本身就是信息）。

正确形态（四方描述措辞不同、指向一致）：

- 每个 agent 是主体（principal），每次读写经主体→能力解析，返回**投影**，被禁字段在返回体里**物理上不存在**
- 权限规则是确定性代码，可穷举测试（参照 `router_exhaustive_test.go` 的主体×资源矩阵），可审计回放
- 动态裁定只允许做内容级（"本章埋哪个钩子、守密强度调多少"），永不碰权限级

**裁决：全盘采纳。** ainovel-cli 的 `build.go` 已有按 agent 装配工具的插入点，`novel_context` 单例无调用方身份是最大泄漏面，改造从这里切。

### 共识 4：MVP 是三臂对照实验，不是功能 demo

| 臂 | 配置 | 检验什么 |
|---|---|---|
| A | 单体全知基线 | 泄底率基线 |
| B | 分工无墙（叙述者可见全量暗账） | 分离"分工本身"的贡献 |
| C | 分工有墙（只见本章钩子投影） | 防火墙的边际贡献 |

两臂无法归因，必须三臂。度量必须双通道：

- **读者模拟器**（LLM，逐章预测"你猜到的真相+置信度+证据句"）测软泄漏
- **金丝雀测试**（非 LLM：暗账条目植入生僻标记词，grep 正文在非回收章的出现）测硬泄漏

同时必须带**反向指标**防作弊：钩子执行率/质量、张力曲线（"想读下一章"1-10 分）。"零泄漏"可以靠"零情节"骗到，这两个指标堵这条路。

判定标准（可证伪）：
- C ≪ A、B 且钩子质量不塌 → 核心假设成立，进入角色 sub agent 实验
- C ≈ B → 行为说成立，转向叙述纪律路线，防火墙降级为辅助
- B ≈ A → 分工本身无用，驳回立项

**裁决：采纳。** 规模定为 12 章 × 约 1000 字 × 3 臂 × 5 次重复（取中位数，LLM 随机性需要方差估计）。读者模拟器用**不同模型家族** + 证据句引用 + 多温度投票；月华作为人工盲评锚点（阮梅坚持的防循环论证保险）。

### 共识 5：真正的瓶颈是一致性仲裁，且与防火墙内生冲突

三人把它列为头号瓶颈（辉夜姬表述为"全知审计员悖论"）。拆开真相持有者之后，"这一章到底发生了什么"没有单一写者；而每次一致性修复（"第 3 章这段与暗账冲突，请改"）本身就是泄漏通道。

辉夜姬给出的解法被采纳为架构原则：**暗账是活的台账**——冲突时优先让事件 agent 修改暗账去迁就已写正文，而不是让正文还债；审计反馈只做最小脱敏（"改哪里、往哪个方向改"，不说为什么）。

**裁决：采纳。** 真理医生的"三层事实合并点"问题，按辉夜姬的分工线收口：**合并点只放在张力曲线层**（事件 agent 独掌），质感层彻底放手给角色涌现。

### 共识 6：读者模拟器必须异构

四方全部警告：读者模拟器与写作 agent 同模型家族 = 裁判和运动员共享盲区，结论系统性偏乐观。

**裁决：采纳。** 模拟器固定为与写作 agent 不同家族的模型，必要时退化为"证据句标记"（半机械化对照暗账语义近邻），不做真相预测。

## 二、分歧与裁决

### 分歧 1：技术栈——Python（黑塔）vs Go 骨架（辉夜姬）

**裁决：MVP 用 Python，引擎期再议。** 理由：MVP 的核心复杂度在 LLM 编排与 embedding 检索，generative_agents 的 retrieve/reflect/whisper 三件套是 Python、移植成本≈0；ainovel-cli 借的是模式（纯函数路由、伏笔三态、checkpoint 纪律），模式跨语言迁移成本远低于算法代码。Go 的类型安全与并发在 12 章实验里用不上。此决策可逆，实验验证后重建引擎时重开讨论。

### 分歧 2：防火墙的粒度——二值开关 vs 连续谱

阮梅（按伏笔条目分级）、辉夜姬（效果指令优先于内容指令 + 泄露率旋钮）、黑塔（字段级裁定："下一章情绪走向可以给，核心事件不能给"）、真理医生（字段物理缺席）四方都反对二值。

**裁决：采纳连续谱。** 防火墙的设计对象是一张**字段级投影表**，进 git 版本库，像代码一样被 review。伏笔数据拆成两件物理记录：

- `hook`：可埋信息（表象描述、情绪基调、显著性），对叙述者可见
- `reveal_plan`：何时如何兑现，事件 agent 独占

"泄露率旋钮"（守密强度参数）进事件 agent 的输出 schema，是项目最需要实验标定的叙事参数。

### 分歧 3：MVP 要不要上角色 sub agent

辉夜姬明确反对（多余组件污染归因），黑塔的配置里含双角色 agent。

**裁决：MVP 用静态人设卡，角色 sub agent 是第二个实验。** 单变量原则：第一个实验只测防火墙。但 generative_agents 的 converse 协议（黑塔已核实 `run_gpt_prompt.py:2821`：对方私有记忆不进 prompt）和 whisper 注入（阮梅评为"全场最有价值的一行代码"）已确认为现成零件，第二个实验直接取用。

## 三、零件清单定案

**原样借鉴（ainovel-cli）**：纯函数路由（router.go）、伏笔三态状态机与 RestoreOwnPlants 重写保护（domain/review.go）、章节提交 Saga、指南针滚动规划、Editor 七维评审的伏笔/钩子量化思路、guard 框架层强制纪律、eval/ 目录的运行器骨架

**原样借鉴（generative_agents）**：记忆流三维检索打分（retrieve.py，recency×importance×relevance，gw=[0.5,3,2]）、反思机制（reflect.py，错误信念的免费来源）、whisper 私有注入（converse.py 的 load_history_via_whisper）、agent_chat_v2 逐句对话协议

**必须从零设计（两个仓库都没有）**：

1. 伏笔暗账的前向字段（hook / reveal_plan 拆分）——ainovel 的台账只记过去
2. 错误信念状态机与信念翻转机制（真相揭示后旧信念节点的 poignancy 重标）
3. 正典 diff 广播（重写后角色记忆里的废弃正史清理，黑塔发现的重写传播问题）
4. 暗账语义指纹拦截器（写作产出命中暗账 embedding 近邻即机械拦截，commit 前强制执行）
5. 泄露率旋钮的标定方法

**明确否决**：导演 agent 裁定权限（全知点回流 + 侧信道）；上下文层摘要式过滤（摘要是有损对称，防火墙要无损不对称，两套机制不可互替）；MVP 期上角色 sub agent（污染归因）
