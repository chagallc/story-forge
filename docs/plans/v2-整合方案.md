# v2 整合方案 · 可抄清单 → story-forge 落地蓝图

> 参谋：朱雀（K3.1-Pro）· 2026-11-04
> 依据：docs/opinions/2026-11-04-引擎扫描报告.md（15 仓库）+ 决策 0003/0005 + workbench v1 现状
> 状态：待月华拍板

## 总路线

**不重写引擎，把现有细胞升级为「章节合约的执行内核」，再补齐正典提交、角色认知和上下文投影。**
动机压力层、信息防火墙、读者模拟器、双检测器、多模型路由全部保留。

## 优先级排序（P0-P8）

| 顺序 | 整合项 | 理由 | 工作量 |
|---|---|---|---|
| P0 | 唯一权威数据源 + spec 派生化 | 后续一切需要稳定数据边界；工作台本无持久化 spec，是低成本定型 | 0.5-1 天 |
| P1 | 章节卡与细胞分层 | 直接改善 discuss→lock：作者目前没有逐项确认目标/选择/后果/读者承诺的机会 | 1-1.5 天 |
| P2 | canon/drafts 分家 + STATE_DELTA + commit | 截断「未审正文自动成为正史」这条链 | 1.5-2 天 |
| P3 | 人物卡四分区 + Learn/Never-Learn | 正典提交出现后角色知识才能逐章可靠推进；金丝雀从「泄漏后报警」推进到「生成前限定可见」 | 1.5-2 天 |
| P4 | HOT/WARM/COLD 上下文投影 | 依赖章节卡和角色知识；太早做只是机械截断 | 1-1.5 天 |
| P5 | 多线推演 | 章节卡先定义候选比较格式，推演才有意义 | 0.5-1 天 |
| P6 | 豁免即状态 | 等 lint/连续性检查有稳定 finding 后再做 | 0.5 天 |
| P7 | 滚动规划 | 12 章规模不紧急；以 canon 提交点为边界展开下一弧 | 1 天 |
| P8 | 修订回灌 | 必须先有 draft/canon 双版本才能取修订 diff；最后做防过拟合 | 1-1.5 天 |

合并交付：**M1 = P0+P1+P5**（讨论可锁定，2-3 天）/ **M2 = P2+P3+P4+P6**（草稿到正史，4-6 天）/ **M3 = P7+P8**（长篇滚动与修订资产，2-3 天）

## 架构裁决一：章节卡 vs 细胞 → 分层，不替换

- **章节卡是作者合约**（这章为什么存在、允许改变什么）
- **细胞是叙事力学**（计划怎么被破坏、动机在哪受压）
- **正文是合约的执行结果**

细胞嵌入章节卡（card.engine 字段），存 `chapters/chNN/card.json`。字段边界：

| 章节卡 | 细胞 | 边界 |
|---|---|---|
| objective | plan | 目标是"要什么"，计划是"准备怎么拿" |
| obstacle | disruption | 阻力原在场；颠覆是使原计划失效的新变化 |
| choice | improvisation | 应变是新战术；选择是作者确认的、有代价的承诺 |
| crisis | intended_consequence | 危机是选择前悬着的代价；后果是选择后的实际状态 |
| recorded_consequence | 无 | 写完正文后填写，供 commit 校验 |

多线推演只生成轻量候选（summary/beats/choice/motive_cost/reader_payoff/risks），选中才展开完整章节卡；候选只写 discussions/，不动 canon/state/ledger。

## 架构裁决二：三层文件，权威无重叠

```
story-bible.json        作者创意与静态设定，唯一人工写入口
state/story-state.json  已提交正史，唯一动态状态权威，只允许 reducer 修改
build/spec.json         引擎投影，可随时删除重建，禁止手改
views/*.md              状态板等派生视图
```

- bible 回答「作者打算写什么」；state 回答「正史发生了什么」；spec 回答「本次写作调用看见什么」
- shadows 继续与 ledger 物理分离，永不进普通写作投影
- bible 增加 schema_version/revision/compass（终局方向+读者承诺+活跃长线）

## 架构裁决三：canon/drafts 分家

```
chapters/chNN/
  card.json / drafts/vNNN.md / drafts/vNNN.delta.json / canon.md / revisions/
```

流程：discuss → 选分支 → lock(card) → write(draft+STATE_DELTA) → 检查 → 人工改 draft → **commit** → canon+state 原子推进。写第 N 章只读 1~N-1 章 canon，绝不读 drafts。新增 revise 命令：改旧 canon 后后续章节标 stale。

STATE_DELTA 白名单操作（learn/set_location/advance_hook…），每 op 必带正文 evidence；commit 校验 base_state_revision；新增 src/harness/state.py reducer（临时文件+os.replace 原子提交+备份）。

## 人物四分区落地

bible::characters[] 存恒定区（anchors 锚点+mes_example 对话样本）/动机区（七字段栈）/知识规则（learn[when 条件]/never_learn）/私有 lorebook（关键词触发）；动态区在 state（knows 带学习章节与来源/unknown_to_them/false_beliefs/location/injuries/inventory/relationships）。动机栈仍对 writer 全量可见——知识区限制事实，不限制作者了解人物内心。

## HOT/WARM/COLD：逐章逐消费者生成投影

- HOT：本章 card+出场人物栈/声口/动态状态+Ledger.directive_for+允许事实+前章 canon 摘要
- WARM：近两章摘要+未闭合 hook+弧锚点+相关关系
- COLD：完整 bible/全部旧正文/shadow/未到期 reveal——默认不注入
- Ledger.full_text() 仅供实验与规划；shadows 永不进 writer 投影；reader 只读 canon

## 风险清单（要点）

- 章节卡字段多收敛慢 → 两阶段讨论（先 3 轻量分支再填完整卡）+ 默认值
- 四分区 prompt 膨胀 → 全量入库≠全量注入；只给出场人物，声口样本取 1 条
- Never-Learn 被绕过 → STATE_DELTA 不靠模型自报入库；正文证据+确定性规则复核，冲突硬拒绝
- 投影截断伤文风 → 短篇保持全文历史；投影版与全文版同章盲读对照后再切
- 修订回灌过拟合 → 人工标原因；同类≥2 次才升级为规则；活跃规则上限 12 条新进旧出
- 旧工作区迁移 → 旧 chNN.md 默认导入 drafts/v001.md，人工 promote 才成 canon

## 一句话总建议

**如果只能先做一件事：先把 lock 改造成「生成并确认章节卡」，现有 cell 原样嵌入 card.engine——它是后续多线推演、上下文裁剪、正典提交和状态回写共同的契约入口。**
