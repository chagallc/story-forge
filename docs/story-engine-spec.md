# 故事引擎层 · 技术说明文档

> Story Forge 架构组件说明。地位：插在暗账（信息层）与写作 agent（执行层）之间，管理"接下来怎么了"。
> 版本：v2（2026-10-11，随决策记录 0002 草案发布）

## 1. 解决什么问题

实验 001 证明：只管理信息可见性（防火墙/暗账）能守住秘密，但产出的故事"一直铺信息、没有抓力"。根因：大纲是事件名词而非计划交易，主角没有可被推翻的计划栈。故事引擎层把叙事驱动（narrative drive）变成可调度的数据结构。

## 2. 三层结构

### 2.1 第一层：弧线（Arc）

骨架模板库，按题材选取，输出**锚点表**（锚点章号按总章数比例伸缩）：

| 模板 | 适用 | 锚点 |
|---|---|---|
| 英雄之旅（Vogler 十二阶段） | 成长/冒险/爽文 | 平凡世界→召唤→跨门槛→试炼→中点磨难→黑暗时刻→复活→归宿 |
| 起承转合（四段式） | 氛围/日常/东方美学 | 起（铺陈）→承（深化）→转（非对抗性扭转）→合（收束） |
| 悬疑假设弧 | 悬疑/推理 | 案发→假设A→推翻→假设B→中点大翻→收网→摊牌 |
| 爽文蓄放弧 | 网文长篇 | 压抑蓄力→爆发释放，分形嵌套于卷弧 |

**长篇分形规则**：>50 章的作品，每卷（8-20 章）实例化一条完整弧线，全书锚点由各卷弧线递归组成。与 ainovel-cli 的卷弧滚动规划同构：写到哪里，下一卷弧线才展开。

### 2.2 第二层：包络（Envelope）

锚点之间的节奏分配。每章一个振幅标签：

| 振幅 | 含义 | 频率约束 |
|---|---|---|
| XL | 计划摧毁 + 底牌回收同炸 | 全书 2-3 次，绑锚点（中点/高潮） |
| L | 大转折（跨门槛级） | 锚点章 |
| M | 计划被迫修正 | 1-2 章一次；XL 前一章必须为蓄力 M |
| S | 信息啃咬/小钩子 | 随时可有多 |
| B | 呼吸拍（sequel：反应-困境-新决定） | **XL 后强制接 B 或低振幅**；全书 ≥2 |

经验参数（网文实战公式，张 3 弛 1；大高潮前 4-5 章蓄力、后 2 章恢复）。

**开环预算**：同时悬置的大问题（XL/L 级未闭合目标）≤ 2，中问题 ≤ 4，小问题随开随关。

**闭环调律**：读者探针逐章回传 {欲望分, 最想知道的问题}；疲劳信号 = 峰值后欲望深跌 ≥3 分，或连续 3 章平坦（方差 < 0.5）。触发动作：插入呼吸拍 / 下调下一峰振幅 / 挪峰位。**只动包络，不动锚点。**

**明确否决**：随机 timer（破坏蓄放因果）；每章 XL（习惯化 → 反转贬值）。

### 2.3 第三层：细胞（Cell，每章四元组）

```json
{
  "chapter": 6,
  "amplitude": "XL",
  "arc_label": "中点磨难",
  "plan": "主角当前计划（读者已知或本章开头可见）",
  "disruption": "颠覆事件：新信息使计划失效（优先燃料=本章暗账回收）",
  "crisis": "危机具象化：失败的代价悬在眼前",
  "improvisation": "临场应变：用新信息当场重构计划（『还可以这样？』的来源）",
  "end_hook": "断章钩子分型"
}
```

断章钩子分型（章末收尾约束）：`新信息型`（刚发现的事改变一切）/ `两难型`（两个都不想要的选项）/ `即将行动型`（下一个动作已扣动扳机）/ `轻收束`（呼吸拍专用）。

### 2.4 与暗账的绑定

- 回收章 = 高振幅章；回收内容作为 `disruption` 的燃料注入，形式必须是"计划崩塌"而非"答案公布"
- 埋设章的 hook 指令照常叠加（物件钩仍在，但服务于本章 plan 的世界）
- 渲染模糊度约束（新增，防"蓝印章"式精度泄漏）：hook 执行时物件描述必须与底牌保持一步之差，由提交校验器检查

## 3. 代码映射

| 概念 | 位置 |

## 4. 验收（实验 002）

1. 盲读者欲望曲线**峰谷对比度**：E1（包络）应呈心跳波形；B1（旧节拍）参照平坦
2. 月华盲读："接下来怎么了"的冲动是否出现
3. 三连反应验收法：怎么会这样？（灾难拍成立）/ 原来是这样？（回收兑现）/ 还可以这样？（应变拍成立）
