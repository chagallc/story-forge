# 实验 001 设计书 · 防火墙能否防止提前泄底

> 决策依据：docs/decisions/0001-立项评审汇总.md（共识 1/2/3/4/6）
> 状态：待首次运行

## 假设与判定标准

**待验证命题**：在分工架构下，对写作 agent 隐藏暗账（防火墙）能显著降低"读者提前猜中底牌"的泄漏率，且不摧毁钩子质量与张力。

| 结果 | 结论 | 后续 |
|---|---|---|
| C ≪ A、B 且钩子质量不塌 | 核心假设成立 | 进入实验 002（角色 sub agent） |
| C ≈ B | 泄底是行为问题，防火墙边际无效 | 转向叙述纪律路线 |
| B ≈ A | 分工本身无用 | 驳回立项 |

## 三臂设计（单变量：写作 agent 的暗账可见性）

| 臂 | 架构 | 写作 agent 可见信息 |
|---|---|---|
| A | 单体（模拟 ainovel-cli 现状） | 前提 + 人物卡 + 12 章大纲 + **完整暗账**（含底牌与金丝雀词） |
| B | 分工无墙（事件指令 + 写作） | 前提 + 人物卡 + 大纲 + **完整暗账** + 本章指令 |
| C | 分工有墙 | 前提 + 人物卡 + 大纲 + 本章指令（**只见 hook 效果指令**，底牌在回收章才随指令放行） |

B/C 的本章指令由同一个**确定性指令生成器**从暗账产出（ledger.py），两臂逐字相同，确保唯一变量是暗账可见性。

## 度量（双通道 + 反向指标）

1. **金丝雀硬泄漏**（非 LLM，确定性）：每条暗账绑一个生僻标记词（蓝鬃/七弦/锡盒/鹤嘴/冰弦），只存在于 reveal_plan 中。grep 各章正文，标记词在回收章之前出现 = 硬泄漏
2. **读者模拟器软泄漏**：逐章输出猜测 JSON（内容/置信度/证据句），回收章前命中底牌 = 软泄漏；猜测与底牌的语义比对在分析阶段进行（judge + 月华人工盲评锚点）
3. **张力曲线**：读者模拟器逐章"想读下一章的欲望 1-10"
4. **成本**：每次调用记 token 台账（usage.jsonl）

## 故事规格

《除夕雪夜》，现代山庄悬疑，12 章 × 约 1000 字，5 条暗账（回收章 6/7/8/9/10）。
大纲只做表层节拍（"书房门锁之谜有解"），不含底牌内容，否则 C 臂会被大纲污染。
完整规格见 `experiments/exp001/spec.json`。

## 模型配置与已知妥协

- 写作：deepseek-v4-pro（temperature 0.8，三臂一致）
- 读者模拟：deepseek-flash（temperature 0.3，朴素读者 persona）
- **妥协项（已记入台账）**：读者与写作同为 DeepSeek 家族，违反共识 6（异构裁判）。正式跑批前必须换血：开 Clash 代理走 OpenRouter（Qwen/Kimi/GLM 任选），或提供第二家厂商 key。烟雾测试阶段可接受
- 预算护栏：每 run 写作 35 万 / 读者 20 万 token 硬上限，超限即停

## 规模

12 章 × 3 臂 × 5 次重复 = 180 章正文 + 180 次读者测量。
烟雾测试：C 臂 2 章，验证管线通畅。
