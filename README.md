# Story Forge · 多智能体长篇小说协作引擎（探索阶段）

## 这个项目要验证什么

单个 LLM 写长篇的两个痼疾：长期设定被提前吐完、伏笔忍不住提前暗示。病根不是注意力长度，而是**单一智能体没有信息隐私**——作者知道的、角色知道的、读者该知道的，全摊在同一个上下文里。

本项目的核心假设：**用多智能体分工 + 信息防火墙重建信息不对称**。

- 背景设定、人物性格、事件触发（正负向）、叙事执行分属不同 agent
- 角色在性格底板之上交给独立 sub agent 生成对话与行为，角色持有**私有认知状态**（包括错误信念）
- 事件 agent 持伏笔暗账，写作 agent 只能查"当前可埋的钩子"，看不到未来走向
- 防火墙规则（每个 agent 被禁止看见什么）是这个项目的真正创作对象

## 目录结构

```
story-forge/
├── README.md              ← 你在看的这份
├── 台账.md                ← 项目流水账：每一步操作、决策、commit 对应关系
├── reference/             ← 第三方参考仓库（git ignore，不入版本库）
│   ├── ainovel-cli/       ← Go 长篇写作引擎：确定性 Engine + Architect/Writer/Editor
│   └── generative_agents/ ← 斯坦福小镇：角色记忆流 / 反思 / 规划
├── docs/
│   ├── review-brief.md    ← 评审任务书（发给每位参与评审的 AI）
│   ├── opinions/          ← 各 AI 的评审意见，一人一文件：<agent>.md
│   └── decisions/         ← 汇总后的决策记录，一次决策一文件
└── src/                   ← （后续）原型代码
```

## 工作流

| 阶段 | 内容 | 状态 |
|------|------|------|
| 0 | 调研：clone 参考仓库，摸清可复用模块 | ✅ |
| 1 | 评审：四位 AI 按 review-brief.md 独立输出意见 | ✅（docs/opinions/） |
| 2 | 汇总：朱雀合并意见，形成决策记录 | ✅（docs/decisions/0001） |
| 3 | 证伪实验：Python 实验台，三臂对照（单体/分工无墙/分工有墙） | ⬜ 待启动 |
| 4 | 原型：依实验结果决定——假设成立则进角色 sub agent 实验，证伪则转叙述纪律路线 | ⬜ |

## 版本控制纪律

1. 每个阶段完成、每次重要决策落地，都对应一次 git commit
2. `台账.md` 与 commit 同步更新，台账记"为什么"，commit 记"改了什么"
3. `reference/` 是第三方只读资料，不进版本库，任何人不得修改
4. 评审意见只增不改；意见被采纳或驳回，结论写进 `docs/decisions/`，原文件不动
